# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project
A small credit underwriting decision service: hard policy rules + a calibrated risk model + a
profit-based approval threshold, served over FastAPI with every decision logged to Postgres.
The goal is production-style code, not notebooks: fewer features done well over many fragile ones.

## Data
Give Me Some Credit (Kaggle, `cs-training.csv`, ~150k rows, target `SeriousDlqin2yrs`).
Downloaded manually to `data/raw/` (gitignored). Public data only — never add anything resembling
real customer or collections data.

## Stack
Python 3.11 · FastAPI · Pydantic · SQLAlchemy · PostgreSQL · pandas · scikit-learn · LightGBM ·
SHAP · pytest · Docker / docker-compose · Anthropic API (monitoring summary only).

## Architecture
```
data/raw/cs-training.csv ─► etl.py ─► Postgres ─► train.py ─► artifacts/ + reports/
                                                                  │
POST /decision ─► api.py ─► decision.py: policy.py rules ─► model score ─► threshold ─► SHAP reason codes
                     └─► log row in `decisions` table
```
- `config.py`: all settings from environment variables.
- `db.py`: SQLAlchemy engine/session and table models.
- `decision.py` evaluates in strict order: hard rules first (a rule hit declines without scoring),
  then model probability of default, then the threshold. Output:
  `{decision, probability_of_default, reason_codes[], policy_version, model_version}`.
  `reason_codes` are the top 3 features by SHAP value.
- `monitoring.py` (optional, last): feature PSI (train vs. a simulated new sample), approval rate,
  and a business-language summary via the Anthropic API.

## Conventions and decisions
- **Artifacts:** `train.py` writes `artifacts/model.joblib` and `artifacts/metadata.json`
  (`model_version`, threshold, metrics, unit-economics assumptions). `artifacts/` is gitignored and
  regenerated by training; the API loads both at startup.
- **Reports:** `reports/` (committed) holds the profit-vs-threshold curve and the assumptions used.
- **Threshold:** chosen by expected profit under explicit assumptions (gain per good payer vs. loss
  per default), never by accuracy.
- **Policy version:** a `POLICY_VERSION` constant in `policy.py`; bump it whenever a rule changes.
- **Tests:** unit tests for `policy` and `decision` need no database. `test_api.py` uses `TestClient`
  and overrides the DB session dependency with in-memory SQLite, so `pytest` runs without Docker.
  Keep table models portable (no Postgres-only column types).
- Code, names, docstrings, README and commit messages in English. Small, descriptive commits.
- `api.py`, `decision.py`, `train.py` and the tests are read on a shared screen: keep functions
  short, names explicit, and the decision flow readable top to bottom.

## Code the owner writes (do not implement)
Leave these as skeletons with clear signatures, docstrings and `TODO`; review what the owner writes.
- The rule bodies in `policy.py` (e.g. minimum age, zero or missing income).
- The threshold-selection function in `train.py`. Claude builds the profit curve, assumptions and
  plumbing around it.
- The body of the `POST /decision` handler in `api.py`. Claude builds the Pydantic request/response
  models, dependencies and `GET /health`.
